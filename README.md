# 楚膳

湖北地域化的智能三餐推荐。根据实时天气、湿度、风力、海拔、时令、预算和菜谱难度，生成早、中、晚三餐建议，并给出「为什么推荐这道菜」的可解释理由。

- 83 道湖北菜谱，覆盖 17 个市州/直管市/林区
- 天气来自 Open-Meteo，免注册、免 key
- 菜价带来源标签（手工/实时简报/指数折算/基线估算），不把估算值伪装成实时行情
- 纯前端，无后端、无账号、无埋点；偏好只存在浏览器 localStorage

## 快速开始

要求 Node.js >= 20（开发环境实测 22.19.0）。

```bash
npm install
npm run dev
```

打开终端提示的地址即可。首次进入会请求浏览器定位权限，拒绝也能用 —— 手动选择市州后获取天气。

## 可用命令

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 启动开发服务器（含菜价接口代理） |
| `npm run build` | 生产构建，产物在 `dist/` |
| `npm run preview` | 预览生产构建 |
| `npm test` | 跑单元测试 |
| `npm run test:watch` | 监听模式跑测试 |
| `npm run validate:data` | 校验菜谱与菜价数据的完整性和取值范围 |

改动菜谱数据后请务必跑 `npm run validate:data`，它会检查难度取值、七个口味维度是否在 0–1 之间、`priceKey` 能否在菜价基准里找到，以及营养宏量与热量是否自相矛盾。

## 数据来源与已知限制

**天气：Open-Meteo。** 免费、支持 CORS、浏览器可直连，海拔由同一响应的 `elevation` 字段给出。中国气象局只有网页端，官方 CMADaaS 接口需机构申请审批，所以这一版用 Open-Meteo。

**菜价：农业农村部全国农产品批发市场价格信息系统（pfsc.agri.cn）。** 这里有几个绕不过去的限制，如实写在这：

1. 「某市场某品种今天多少钱」的接口被图形验证码锁死。按省查询能返回湖北 7 个市场，但价格字段全是 null。
2. 能稳定拿到的只有每日价格指数（农产品200/粮油/菜篮子）。
3. 每日行情简报里含猪肉、牛肉、鸡蛋等约 8 项真实价格，但该接口时好时坏，只能当 best-effort。

所以每个价格都带 provenance 标签：`manual`（你自己填的）> `live`（简报真实价）> `index-adjusted`（基线 × 今日指数/基线日指数）> `baseline`（静态兜底）。**显示出来的多数价格是全国指数折算的估算值，不是湖北本地批发价。** 界面上提供手工改价，填你在菜场看到的真实价会覆盖估算值并存进 localStorage。

**部署注意：** 菜价接口靠 Vite 的开发代理转发（浏览器直连会被 CORS 和 WAF 拦）。`npm run build` 出来的静态产物没有这层代理，直接扔到静态托管上菜价会拉不到，只会落到 baseline 兜底。要在生产环境拿到菜价，得自己在前面放一层反向代理，把 `/pfsc` 转到 `https://pfsc.agri.cn`。

## 项目结构

```
src/
  api/          天气、菜价数据层，含 fetch 封装（超时/重试/缓存）
  engine/       推荐引擎，全是纯函数
    context.js  天气读数 → 环境画像（体感带、湿度带、海拔带、节气、梅雨、三伏）
    demand.js   环境画像 → 七维口味权重向量
    score.js    权重 × 菜品属性 + 成本契合 − 惩罚 + 确定性抖动
    cost.js     配料 × 菜价 → 家做成本估算
    region.js   市州代表菜加权
    plan.js     餐段规则与三餐组配（中餐按主菜/素菜/汤组合）
  data/         菜谱、城市、菜价基准、检索出处
  components/   Vue 组件
  stores/       全局状态（Vue 响应式原语手写，未引 Pinia）
scripts/        数据校验
tests/          单元测试
```

引擎全部是纯函数且不依赖浏览器 API，可以脱离界面单独测试。推荐结果的抖动用菜品 id 的确定性哈希，同一天同一城市的结果是稳定的，不会点一次刷新就换一批。
